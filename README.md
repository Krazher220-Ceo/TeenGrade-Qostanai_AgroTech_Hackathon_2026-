# AgroVision AI — мониторинг сорняков с БПЛА

Проект команды для кейса №1 Qostanai AgroTech Hackathon 2026.

Мы превращаем обычный снимок поля с дрона в понятную для агронома карту: где находятся сорняки, к какому виду они относятся, на какой стадии роста находятся и какие объекты модель считает сомнительными. Культурные растения отделяются от сорняков, чтобы не включать их в карту опрыскивания.

## Что уже работает

- детекция растений на больших DJI-снимках через YOLOv8s с тайлингом и объединением пересекающихся рамок;
- классификация объекта через EfficientNet-B0: бодяк, вьюнок, пырей и пшеница/фон;
- определение стадии `Розетка` или `Стеблевание` для сорняков;
- безопасные статусы `unknown` и `review_required` при низкой уверенности;
- действие `do_not_spray` для распознанной культуры;
- выгрузка результатов в JSON, CSV, отдельные crops и размеченные изображения;
- FastAPI API и интерактивный Streamlit-дашборд;
- загрузка собственного снимка поля в Streamlit с выгрузкой annotated image, CSV и JSON;
- 34 автоматических теста моделей, API, viewer workflow и планировщика флота.

Проверено локально 17 сентября 2026 года: обе модели загружаются, API проходит smoke-тесты, а полный конвейер успешно обработал пять исходных DJI-снимков. Получено 660 детекций, 660 отдельных crops, пять размеченных кадров и итоговые JSON/CSV.

В текущем 4-классовом прогоне модель отнесла 558 объектов к пшенице/фону, 69 — к трём целевым видам сорняков и 33 — к `unknown`. Эти числа показывают работу конвейера, но не являются метриками качества без ручной разметки полевых кадров.

## Как устроен конвейер

1. Большой кадр с дрона режется на перекрывающиеся тайлы 1280 × 1280.
2. WeedBlaster YOLOv8s находит растения класса `Weed`.
3. Global NMS убирает дубли на границах тайлов.
4. EfficientNet-B0 определяет вид и стадию каждого объекта.
5. Объекты с низкой уверенностью отправляются на ручную проверку.
6. Результаты сохраняются в CSV/JSON и показываются в дашборде.

## Быстрый запуск

Нужен Python 3.11. Все команды выполняются из корня проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r case1/requirements.txt
```

Проверка окружения и моделей:

```bash
python case1_main.py status
python case1_main.py test
```

Обработка всех локальных снимков:

```bash
python case1_main.py process
```

Можно передать один собственный снимок и отдельную папку для результата:

```bash
python case1_main.py process --image /path/to/drone-image.jpg --output demo-output
```

Запуск интерфейса:

```bash
python case1_main.py dashboard --port 8501
```

После запуска страница доступна по адресу `http://localhost:8501`.

Запуск API:

```bash
PYTHONPATH=. uvicorn case1.server.app:app --host 127.0.0.1 --port 8000
```

Swagger: `http://127.0.0.1:8000/docs`.

## Модели и данные

Для полного запуска нужны два checkpoint-файла:

- `weedblaster-vision-yolov8s/best.pt` — детектор;
- `case1/models/multitask_weeds_best.pt` — классификатор вида и стадии.

Детектор можно восстановить командой:

```bash
python case1_main.py download-weights
```

Большие модели должны храниться в Git LFS. После клонирования репозитория выполните `git lfs pull`. Исходный датасет не следует загружать в обычный Git; ожидаемая локальная структура описана в `case1/data/manifest_v2.csv`.

## Подтверждённые метрики

Последний завершённый отчёт `case1/output/classifier_training_metrics.json` относится к новой 4-классовой модели: три целевых вида сорняков и отдельный класс `crop_wheat`. Обучение завершено на разбиении `train=610`, `val=134`, `test=153`.

| Метрика | Значение |
|---|---:|
| Accuracy по видам | 91,5% |
| Macro-F1 по видам | 0,902 |
| Accuracy по стадии | 100% |
| Macro-F1 по стадии | 1,000 |

Recall по классам: бодяк — 97,1%, вьюнок — 67,7%, пырей — 100%, пшеница — 98,5%. Главная слабость модели сейчас — вьюнок: почти треть его тестовых примеров может быть пропущена. Метрика стадии рассчитана только для объектов с валидной разметкой стадии и не означает безошибочную работу на новых полях.

## План развития: офлайн-флот из нескольких дронов

Отдельный инженерный разбор сценария с пятью аппаратами, расчётом покрытия, ограничением бюджета 500 000 ₸, офлайн-архитектурой и правилами безопасности находится в файле [`drone_fleet_offline_research.md`](drone_fleet_offline_research.md).

Коротко: на хакатоне корректно демонстрировать пять аппаратов в симуляции и один физический прототип, если он доступен. Покупку пяти полноценных автономных опрыскивателей за указанный бюджет и их управление одним агрономом проект не заявляет как уже реализованную возможность.

## Честные ограничения

- Текущая модель проверена на небольшом хакатонном наборе и не готова к промышленному применению без полевой валидации.
- Метрика 100% по стадии получена на ограниченном тестовом наборе; это не означает 100% точность на новом хозяйстве.
- У пырея нет полноценного эталона стадии розетки, поэтому такая комбинация переводится в `unknown`.
- Экономические расчёты и нормы препаратов в дашборде являются демонстрационными. Решение по обработке принимает агроном с учётом культуры, регламента препарата и условий поля.
- Детектор основан на сторонней модели WeedBlaster с лицензией AGPL-3.0; перед публикацией продукта необходимо проверить совместимость лицензий всех данных и моделей.

## Что обязательно сделать перед отправкой репозитория

- включить Git LFS и убедиться, что оба `.pt` загружаются после чистого клонирования;
- сохранить checkpoint и отчёт 4-классового обучения через Git LFS либо воспроизводимое внешнее хранилище;
- проверить `python case1_main.py test` на чистом окружении;
- добавить сведения о команде и собственную лицензию проекта.

Главный критерий готовности простой: новый человек должен клонировать репозиторий, выполнить команды из раздела «Быстрый запуск» и увидеть рабочий результат без устных пояснений от команды.
