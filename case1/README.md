Проект — MVP для кейса хакатона, не сертифицированный продукт или разрешение на автоматическое опрыскивание.

## Быстрая оценка проекта проверяющим

Полная инструкция с нуля (Git LFS, Docker, HTTPS для PWA) — [`docs/RUN.md`](../docs/RUN.md). Коротко, из корня репозитория:

```bash
git lfs pull
make setup
make test
make dashboard   # http://localhost:8501
```

Начните с вкладки **«Проверить снимок поля»**: загрузите JPG/PNG до 50 МБ, запустите распознавание, посмотрите размеченное изображение и очередь ручной проверки, скачайте CSV/JSON. Затем вкладка **«Планирование флота»** — расчёт миссии для 1–5 БПЛА.

Первый прогон большого DJI-кадра на CPU может занять несколько минут из-за тайлинга и покадровой классификации.

## Основной пользовательский сценарий: один снимок → готовая сводка

Вкладка Streamlit «Проверить снимок поля» реализует сценарий без командной строки:

```text
JPG/PNG
  → проверка типа и размера
  → тайлинг 1024–1280px с overlap 20%
  → YOLOv8 детекция crop/weed
  → IoM-слияние рамок
  → геопривязка каждого объекта (EXIF → lat/lon)
  → crop каждого объекта
  → EfficientNet-B0: вид (26 классов) + фаза (3 класса)
  → safety gate: вид подтверждается только при species_conf ≥ 0.75
  → crop исключается из карты обработки; сорняки и manual_review остаются
  → аннотированный кадр + crop-галерея + CSV + JSON
```

Каждый запуск получает стабильный ID по SHA-256 загруженного файла, артефакты — в `case1/output/viewer_runs/<run_id>/`.

| Файл | Содержимое |
|---|---|
| `input.*` | Исходный кадр |
| `detector_boxes/detector_boxes_input.*` | Рамки-кандидаты YOLO до классификации |
| `annotated/annotated_input.*` | Рамки с видом/фазой/уверенностью, культура исключена |
| `crops/input/` | Отдельные вырезки каждого объекта |
| `all_fields_detections.csv` | Одна строка на объект |
| `all_fields_report.json` | Сводка кадра со вложенными детекциями |

Даже при нуле детекций CSV создаётся с полным заголовком, JSON — со сводкой обработанного кадра.

### Формат CSV (одна строка на объект)

| Группа | Поля |
|---|---|
| Идентификация | `image_id`, `object_id` |
| Детектор | `detector_conf`, `bbox_x1/y1/x2/y2`, `bbox_width/height` |
| Геопривязка | `lat`, `lon`, `geo_quality`, `geo_error_m` |
| Вид | `species`, `species_ru`, `species_conf` |
| Фаза | `stage`, `stage_ru`, `stage_conf` |
| Safety | `spray_action`, `review_required` |
| Метаданные кадра | `drone_lat`, `drone_lon`, `drone_abs_alt`, `drone_rel_alt`, `timestamp` |
| Аудит | `crop_path` |

### Формат JSON (одна запись на снимок)

`filename`, `time_s` (время детектора без UI-overhead), `total_weeds`, `review_required_count`, `counts_by_species`, `counts_by_stage`, `avg_species_conf`, `annotated_image`, `agronomy_evaluation` (плотность/м², ЭПВ, фазовая дозировка, кинематика форсунок), `detections` (полный список объектов).

## Планировщик флота (1–5 БПЛА)

### Алгоритм
1. WGS84-полигон переводится в локальные метры через `pyproj`.
2. Из рабочей области вычитаются exclusion zones.
3. Рассчитываются footprint, GSD, шаг полос и trigger interval.
4. Проверяются кандидаты угла покрытия, полосы пересекаются с допустимой геометрией.
5. Dynamic programming распределяет смежные полосы между 1–5 аппаратами.
6. Назначаются `system_id`, UDP-порт, площадка; выполняется статическая safety-валидация.
7. Экспорт в JSON, GeoJSON, SQLite, QGroundControl `.plan`.

### KPI демонстрационного поля (23.4 га, высота 30 м, скорость 5 м/с, 5 аппаратов)

| KPI | Значение | Тип доказательства |
|---|---:|---|
| Покрытие | 23.3 га / 99.5% | Расчёт геометрии |
| Полосы | 41 | Планировщик |
| Время флота (5 БПЛА) | 1044 с / 17.4 мин | Модель параллельной миссии |
| Время одного аппарата | 4848.7 с / 80.8 мин | Модель сравнения |
| Ускорение | 4.64× | Расчётное, не flight benchmark |
| GSD | 1.20 см/px | Оптическая модель |

`99.5%` — покрытие полосами в 2D-модели, не процент уничтоженных сорняков и не доказательство безопасного группового полёта.

## PX4/Gazebo/QGroundControl (единственный проверенный лётный тест)

На Apple Silicon Mac проверены QGroundControl 5.1.4, PX4 commit `fe87271`, Gazebo Sim 8.15.0, один аппарат x500: heartbeat получен, взлёт на ≈2.23 м, посадка, разоружение, `.ulg`-лог 26 675 364 байта.

```bash
cd /path/to/PX4-Autopilot
make px4_sitl gz_x500
```

В `pxh>`: `mavlink status`, `commander takeoff`, `listener vehicle_local_position -n 1`, `commander land`.

Загрузка проектного `.plan` и одновременный запуск пяти экземпляров ещё не проверены. Для документированного PX4 multi-vehicle Gazebo-сценария нужна отдельная Ubuntu-среда и актуальная инструкция PX4.

## Принципы разработки

| Принцип | Как применён |
|---|---|
| Evidence before claims | Метрики только из JSON/CSV/логов тестов; см. `docs/MODEL_CARD.md` |
| TDD | Geometry, partitioning, safety, geo/zones/isoxml, HITL покрыты тестами до или вместе с кодом |
| Human-in-the-loop | Низкая уверенность → `manual_review`, финальное решение — за агрономом |
| Offline-first | PWA и результаты сохраняются локально, синхронизация — при появлении сети |
| Reproducibility | Команды, манифесты, чекпойнты и SHA зафиксированы в `MANIFEST.md` |
| Domain-shift awareness | Полевые метрики классификатора показаны отдельно от лабораторных, не смешиваются |
| Honest scope | Расчётный/демо-статус не выдаётся за подтверждённый полевой факт |

## Roadmap

### Выполнено
- аудит данных и чекпойнтов, detector + multi-task classifier (26 видов/3 фазы);
- геопривязка отдельного сорняка, зоны обработки, экспорт GeoJSON/Shapefile/ISO 11783-10 Grid Type 2;
- HITL-экспорт верификаций и дообучение (ручной promote), реестр многолетников;
- единый порог ручной проверки (0.75) во всех модулях;
- Docker/Compose, HTTPS-скрипт для PWA, CI (GitHub Actions), `docs/RUN.md`;
- планировщик 1–5 аппаратов, единичный PX4/Gazebo smoke-flight.

### Дальше — подтверждение ML
- ручная bbox-разметка кадров DJI для независимого поля/day-holdout;
- XSD-валидация ISO-XML и приёмочный тест хотя бы на одном реальном терминале;
- калибровка confidence/threshold на реальном полевом распределении, а не на лабораторных фото;
- ECE/Brier calibration error, per-class recall на полевых данных.

### Дальше — подтверждение миссии
- импорт `.plan` в QGroundControl и полная миссия с `.ulg`;
- 2, затем 5 SITL-аппаратов одновременно;
- link-loss/low-battery/RTL/geofence, minimum separation по телеметрии.

### Полевой пилот
- экспертная разметка и protocol approval;
- shadow mode без реального опрыскивания, затем controlled plot с ручным подтверждением;
- журналирование, rollback, отдельный safety case (авиационный + агрономический).

## Лицензии и безопасность

- Детектор дообучен поверх Ultralytics YOLOv8 — **AGPL-3.0**; для коммерческого/закрытого использования нужна либо коммерческая лицензия, либо замена архитектуры детектора. Подробности — `docs/MODEL_CARD.md`.
- Классификатор (EfficientNet-B0, `torchvision`) — BSD.
- `human_confirmation_required` остаётся обязательным для сомнительных случаев.
- Реальный многодроновый полёт требует отдельного лётного допуска.
- Agronomy output — decision support, не рецепт без агронома.

Главный критерий: **каждая цифра связана с воспроизводимым файлом, тестом или логом; расчётное/демо явно помечено как расчётное/демо**, а не как измеренный полевой факт.
