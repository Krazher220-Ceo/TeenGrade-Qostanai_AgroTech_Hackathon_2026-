## 1. Детектор кандидатов — YOLOv8s (`crop` / `weed`)

### Назначение
Находит на кадре бокс-кандидаты двух классов — `crop` (культура, пшеница) и `weed` (сорняк любого вида). Дальше каждый бокс вырезается и передаётся классификатору. Детектор не различает виды сорняков — это задача второй модели.

### Файл весов
`case1/models/weed_detector_finetuned.pt` (SHA-256 в `case1/models/server_2026-09-17/MANIFEST.md`: `34b0935e...`).

### Архитектура и обучение
- Базовая архитектура: YOLOv8s (Ultralytics), предобучена на CropAndWeed (Австрия, 9 классов) как `weedblaster-vision-yolov8s/best.pt`.
- Дообучение (`case1_main.py train-detector`) на объединённом датасете `yolo_combined`: **2 506 кадров, 9 971 бокс** (`crop` 1 622 / `weed` 8 349, дисбаланс ≈ 5.1:1), 25 эпох, аугментации Mosaic/HSV/Random Perspective. Конфиг: `case1/configs/combined_detector.yaml`.
- Датасет собран из 6 источников (`case1/data/dataset_catalog.json`): `weed_crop_aerial` (1 176 кадров, БПЛА), `crop_weed_detection` (1 300, наземная съёмка), `grass_weeds` (2 486), эталонные фото кейса (552) и 5 снимков DJI. Итог каталога — 6 071 кадр / 17 275 боксов по всем источникам; на конкретно `yolo_combined`, на котором обучен боевой чекпойнт, — 2 506/9 971 (см. `docs/overall-metrics-audit-2026-09-18.md`, раздел 1.2 — старое README указывало «2 926/10 671», это не подтверждается).

### Метрики (независимый тест, воспроизведён на GPU-сервере 2026-09-18)

| Выборка | mAP@50 | mAP@50-95 | mean P | mean R | Файл |
|---|---:|---:|---:|---:|---|
| Полный тест, 381 изображение (313 реальных + 56 синтетических copy-paste + 12 пустых негативов) | 0.7715 | 0.4858 | 0.7383 | 0.7311 | `case1/output/server_2026-09-17/eval/detector_test_metrics.json` |
| Только реальные изображения, 313 | 0.7571 | 0.4713 | 0.7282 | 0.7284 | `case1/output/server_2026-09-17/eval/detector_test_real_only_metrics.json` |

По классам (полный тест): `crop` P 0.7244 / R 0.7489 / mAP50 0.7820 / mAP50-95 0.5405; `weed` P 0.7521 / R 0.7132 / mAP50 0.7610 / mAP50-95 0.4311. На «чистых» реальных изображениях mAP50-95 класса `weed` падает до 0.4010 — синтетические copy-paste тайлы слегка завышают метрику по сорнякам (детали — `docs/server-eval-2026-09-18.md`, раздел 2.2).

Матрица ошибок (полный тест, сырые счётчики; `[crop, weed, background]`):

```

pred_crop            178         11           71
```

Ложные срабатывания на чистой почве: **1 бокс на 12 пустых негативных тайлах** (8.3% изображений с хотя бы одним FP, conf ≥ 0.25) — `case1/output/server_2026-09-17/eval/negatives_fp_report.json`.

Метрики валидации при обучении (эпоха 25, `val=True` только на последней эпохе): mAP50 0.804, mAP50-95 0.496, P 0.706, R 0.769 — `case1/output/server_2026-09-17/results.csv`, `case1/output/server_2026-09-17/MANIFEST.md`. Это метрика на val-сплите обучающего прогона, не независимый holdout-тест; используйте цифры из таблицы выше как основные.

### Ограничения
- Обучен на смеси источников с разным углом съёмки, высотой и освещением; доля синтетических copy-paste тайлов в тесте (56 из 381) завышает метрику по классу `weed`.
- Не различает виды и фазы — это задача классификатора.
- Не тестировался на кадрах вне выборки кейса (другие поля, культуры, сезоны).
- AGPL-3.0 (см. раздел «Лицензии» ниже).

### Как воспроизвести
```bash
python case1_main.py build-detector-dataset
python case1_main.py train-detector --epochs 25 --batch-size 8
# независимый тест на сервере/локально:
yolo val model=case1/models/weed_detector_finetuned.pt data=case1/configs/combined_detector.yaml split=test
```

## 2. Классификатор вида и фазы — EfficientNet-B0 (multi-task)

### Назначение
На вырезке одного объекта определяет вид растения (26 классов, включая `volunteer_wheat` — падалицу пшеницы) и фазу развития (3 класса). Пшеница как культура не входит в число классов вида — она отсекается детектором (класс `crop`) раньше, до классификатора.

### Файл весов
`case1/models/multitask_weeds_best.pt` — модель по умолчанию (26 видов / 3 фазы). Старая 4-классовая модель сохранена отдельно как `case1/models/multitask_weeds_legacy_4cls.pt` и не используется по умолчанию ни в одном модуле (`case1/server/app.py`, `case1_main.py`, `case1/ml/latency_benchmark.py`, `case1/ml/cluster_analysis.py`, `case1/ml/export_mobile.py` — все указывают на `multitask_weeds_best.pt`).

### Архитектура и обучение
- Backbone: EfficientNet-B0 (`torchvision`), две головы — species (26 выходов) и stage (3 выхода).
- Функция потерь: Focal Loss (γ=2.0) для дисбаланса редких видов.
- 15 эпох, 1418 с обучения (`case1/output/classifier_training_metrics.json`).
- Данные: train/val/test = 7 132 / 1 503 / 1 591 кропов (эталонные фото + аугментации из `Dataset 1 кейс/Сорняки`, объединены с падалицей пшеницы/фоном).
- Список классов вида и фаз: `case1/models/species_mapping.json` (`num_classes: 26`, `num_stages: 3`, фазы — `cotyledon_to_2_leaves`, `4_to_6_leaves`, `over_6_leaves_or_flowering`).

### Метрики

| Метрика | Значение | Условия | Файл |
|---|---:|---|---|
| Species accuracy | 0.9843 | 1591 тестовых кропов, эталонные фото крупным планом | `case1/output/classifier_training_metrics.json` |
| Species macro-F1 | 0.9837 | там же | там же |
| Stage accuracy | 0.9874 | там же | там же |
| Stage macro-F1 | 0.9850 | там же | там же |

**На реальных кадрах дрона** (40 изображений, 4 поля, 711 детекций, `case1/output/server_2026-09-17/field_eval/field_eval_summary.json`):

| Метрика | Значение |
|---|---:|
| Медианная уверенность вида (species_conf) | 0.49 |
| Средняя уверенность вида | 0.52 |
| Доля детекций с species_conf < 0.65 | 67.8% |
| Доля детекций с species_conf < 0.50 | 52.0% |
| Ушло на ручную проверку (при пороге теста 0.60) | 63.85% (454 из 711) |

Порог теста на момент этого прогона был 0.60; сейчас единый порог в проде — 0.75 (`case1/configs/settings.yaml → review.species_confidence_threshold`), то есть доля объектов, уходящих агроному на реальных кадрах, сейчас не ниже показанной здесь.

### Ограничения
- Разрыв «студия vs дрон» (domain shift): 98.4% — метрика на кадрах, снятых в тех же условиях, что и обучающая выборка (крупный план, контролируемое освещение), а не на реальных мелких вырезках с БПЛА.
- Редкие виды представлены малым числом примеров; per-class recall не публикуется в этой карточке — см. `case1/output/classifier_training_metrics.json → test_metrics.species_recall_per_class` для полного списка по всем 26 видам.
- Классификатор не оценивает многолетность растения по возрасту/размеру — деление на однолетние/многолетние виды зашито в справочник (`case1/fleet/agronomy_rules.py → PERENNIAL_SPECIES_CODES`), а не выводится моделью.
- Лицензия — BSD (`torchvision`, EfficientNet).

### Как воспроизвести
```bash
python case1_main.py train-classifier --epochs 35
python case1_main.py process --detector finetuned --output case1/output
```

## 3. HITL-дообучение (для полноты — не отдельная выпущенная модель)

`case1/ml/finetune_hitl.py` дообучает копию `multitask_weeds_best.pt` на смеси исходного датасета и подтверждённых решений агронома (`case1/data/manifest_hitl.csv`, собирается `case1/ml/hitl_export.py` из `server_ledger`). Кандидат всегда сохраняется отдельно в `case1/models/hitl/` и сравнивается с текущим чекпойнтом на отложенной выборке (`decide_promotion`); замена рабочей модели — ручное действие, а не автоматика. На момент написания карточки в репозитории нет опубликованного HITL-кандидата с собственными метриками — раздел появится, когда будет накоплено достаточно верифицированных решений в поле.
